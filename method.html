Data and sampling

The analysis begins from NVAtlas-AI-Agent.csv, supplied for this project on 5 November 2026. It contains 500 rows with unique sentence IDs and five original fields: id, English, Chinese, English_Nominal, and Chinese_Verb. The sentence IDs span 168 to 304,712 and are sorted in ascending order. The CSV contains 488 unique English strings and 488 unique Chinese strings, so twelve rows repeat at least one side.

Sampling status: not yet documented. The file does not state its population, candidate count, inclusion filters, random seed, or collection date. It should not be described as a random or representative sample. Before submission, replace this paragraph with the actual extraction procedure and number of rejected candidates.

The source field currently combines a sample label with the sentence ID, for example “NV Atlas AI Agent sample, sentence id 168.” It is traceable to a row in the supplied file but not yet to an external corpus URL. The original CSV and enriched CSV are both retained in the repository so that added metadata can be audited against the source.

Codebook

The codebook has three mutually exclusive categories. The classification unit is the English key term, not the full sentence. The same rule is applied to every row so the categories can be recomputed and audited.

01 · action

Action nominalisation

Definition: a noun denoting an act, event, or process that can be expressed as a verb.

Theory source: transposition in Vinay and Darbelnet; nominalisation as a grammatical metaphor in systemic functional linguistics (Halliday).

Decision rule: code as action when the English key term ends in -tion or -sion.

Positive example: protection → 保護 (“I needed protection.”). Negative example: agreement → 同意, which ends in -ment and therefore belongs to result.

Boundary case: attention ends in -tion but may denote a state of readiness rather than an event. It remains in action because the rule is morphological and reproducible; the semantic mismatch is recorded here.

02 · result

Result nominalisation

Definition: a noun that presents an act through its outcome, product, or settled state.

Theory source: transposition and grammatical metaphor; the category separates -ment forms from the broader -tion/-sion group for descriptive comparison.

Decision rule: code as result when the English key term ends in -ment.

Positive example: appointment → 預約 (“Have you an appointment, sir?”). Negative example: action → 開拍, which does not end in -ment and belongs to action.

Boundary case: government can name an institution rather than a result. It remains in result under the suffix rule; this limitation is acknowledged rather than silently corrected.

03 · state

State / quality nominalisation

Definition: a noun naming a condition, quality, or relation rather than a bounded event or its product.

Theory source: descriptive classification informed by transposition; this is a residual class for terms outside the two productive suffixes.

Decision rule: code as state when the English key term does not end in -tion, -sion, or -ment.

Positive example: defence → 辯駁 (“anything to say in defence”). Negative example: decision → 決定, which ends in -sion and belongs to action.

Boundary case: pleasure can be an event or a state. It remains in state because the suffix rule is the only consistently applied decision procedure.

Revision log — v1.0, 5 November 2026: initial rule set. The first draft used a semantic category named “event”; review showed that only 105 rows were assigned by that label and that it overlapped with action. The rule was replaced by the suffix-only schema above. The change was made to remove subjective judgement from the automatic pass and to make a fresh manual annotation possible.

Quality checks

Automated checks completed in this build: all 500 rows load; every row has non-empty source_text, target_text, source, category, human_checked, key_term, and target_key_term; all sentence IDs are unique; the category rule assigns one of exactly three values; and the site’s total count matches the dataset length. The JavaScript syntax was checked with Node.js.

Manual spot check still required. The assignment asks for at least 50 randomly sampled rows checked against the original source, with errors corrected and those rows marked human_checked = yes. That check cannot be completed until the original source and sampling record are available. No false verification is marked on this site.

Known limitations

  • The corpus’s external provenance, sampling seed, filters, and candidate pool are not documented in the supplied file.
  • The source field identifies an ID within the supplied sample but not the original corpus record URL.
  • Categories are morphological proxies. They are reproducible, but they do not fully represent semantic roles.
  • All human_checked values are currently no. The required 50-entry manual verification remains outstanding.
  • Some Chinese fields contain mixed Traditional/Simplified forms. The original text was not normalised, because changing it would make source comparison harder.
